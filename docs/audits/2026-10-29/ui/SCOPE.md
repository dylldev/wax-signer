# Wax UI audit scope

Audit Wax's existing interface, accessibility, task flows and responsiveness. Preserve the cream/burgundy palette, wax-seal identity and all working signing, recovery and installation behavior.

Render actual screens in the simulator; distinguish source evidence, runtime observations and proposals. Record limitations rather than inventing screenshots or performance gains.

Implement confirmed low-risk UI defects in an isolated branch. Larger navigation rewrites and subjective design directions remain reviewable proposals. Add no paid services or unnecessary dependencies. Preserve existing uncommitted work and real credentials. Do not upload private IPAs, merge, deploy or publish releases.

Deliver the ten requested audit reports, evaluated improvement ideas, before/after evidence, test results and a review PR. A complete free-only consequential review remains a separate gate; a draft PR does not bypass it.
