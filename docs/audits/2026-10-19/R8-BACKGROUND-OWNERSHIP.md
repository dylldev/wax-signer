# R8 milestone — Explicit background-resource ownership

Stacked on R3 `469a10e`. Separate from independent loopback PR #13; no dependency code is duplicated. General OTA/session coordinator and cooperative pipeline cancellation remain unfinished.

Original R2 `App/BackgroundJob.swift:45–57` overwrites one grace identifier/title each begin, `:71–80` ends whichever job happens to own global state, and expiration (`:30–37`) checks only task != nil, so a stale callback can complete a different system task. SourcesModel allows concurrent app downloads; completion of one previously ended another's shared task. Signing and downloads use the same singleton.

`begin` now returns UUID ownership. Every source/sign/install caller retains and supplies that token for progress/end. Nested signing inside an install updates its outer token; standalone signing owns a separate one. Each operation owns a separate grace task and halfway notification. Ending a token is idempotent and releases only its grace handle. Stale progress/unknown tokens cannot change other jobs.

A carefully defined aggregate continued-processing task covers active operations: request only on empty-to-nonempty transition; end only when all active operations end; failure cannot be overwritten by later success; completed jobs remain in progress weighting until the group ends. A late queued task with no active work is completed false immediately, never retained. Unexpected duplicate adoption is completed without replacing the current task. Expiration checks exact handle identity and completes it once; a stale expiration cannot end a replacement. Pending aggregate requests are canceled only after the group empties. iOS refusal/expiration still limits background execution; this PR does not promise unlimited runtime or cancel synchronous crypto/signing on expiry.

Ten deterministic app-model regressions use a small system-resource adapter rather than constructing Apple-owned BGTasks. Cases: overlapping resources; aggregate failure; late adoption; stale expiration; expiration/end exactly once; duplicate adoption; per-job grace expiry; independent halfway/stale progress; aggregate progress/nonfinite fractions; immediate expiry during admission. The production adapter still uses actual UIKit/BGTaskScheduler APIs and retains the shipped identifier. Existing R3 model/persistence tests remain enabled.

Local offline Swift6 syntax parse/diff check passed; Linux lacks UIKit/BackgroundTasks, so model execution and unsigned iOS integration must pass final macOS CI. Simulator adapter tests verify lifecycle policy, not iOS background scheduling behavior. Physical iOS26 continued processing, earlier-iOS grace, lock/foreground transitions, permission/refusal and termination remain separate gates. No device/phone performance claim. New test adapter is internal; no framework/dependency or signing behavior change.
