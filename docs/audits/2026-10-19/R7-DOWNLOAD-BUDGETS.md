# R7 milestone: enforce source/IPA transfer budgets

Baseline `8ad4b2e`: SourceStore checked its 64 MiB maximum only after downloading the whole response, and IPADownloader had no received-byte limit or total deadline. Its cancellation hook could run before task registration and lose cancellation. These paths are acquired before R3 library saving; they do not change signing/archive integrity.

A SourcesKit-local bounded transport now writes decoded URLSessionDataDelegate chunks into a unique 0600 owned file. It checks actual bytes before each write, uses declared size only for early refusal, checks final written length, enforces a monotonic total timer even with no response/body, probes free space before transfer and at 8 MiB intervals, requires HTTPS throughout at most five redirects and propagates disk/deadline/size errors. Cancellation is registered under a lock and finalizes once even when the underlying transport does not deliver another callback. Failure removes only the owned partial, never previous artifacts. No whole IPA buffer is introduced. Source cap remains at most 64 MiB; public DownloadBudget defaults IPA to 2 GiB/30 minutes/16 MiB minimum reserve and can be configured by callers. Content-Length/app.size are not identity or budget proof.

A dedicated foreground session uses the injected configuration, preserving test URLProtocols, cookies/cache and TLS settings. Unsupported custom delegates/background configurations fail explicitly rather than silently dropping a custom trust policy. This is an intentional compatibility restriction; actual Wax callers use ordinary foreground/default sessions. Separate connection pools may add TLS setup overhead (not benchmarked). Default TLS verification is unchanged.

Ten new tests cover exact/oversized/unknown/lying lengths, source budget, insufficient disk, silent-server total deadline, pre-start cancellation, HTTPS/redirect downgrade, invalid limits and refusing a dropped custom delegate. Available environment: actual SourcesKit sources/tests copied to a temporary Swift package with FoundationNetworking imports only; **37 XCTest cases passed, zero failures** using offline Swift 6.2.3 Linux. One redirect test is excluded only from that temporary Linux command because corelibs URLProtocol redirect callbacks are unsupported; the committed test remains enabled for macOS CI. Initial transport experiment compiled but stalled on completion-after-cancellation; direct once-only finalization and a proper data-delegate session fixed it. No Linux success is claimed to prove Apple/iOS behavior.

Command: offline Swift container `timeout 55 swift test --skip testHTTPSRedirectCannotDowngradeTransport` in the temporary SourcesKit package; focused eight budget tests also passed. Production repository tests are unchanged except new regressions; final macOS CI is required. R1 gzip/uncompressed TAR cap is already present in DebExtractor.decompress and is preserved.

**Original R7 remains partially implemented**: credential/local-file early read budgets, InstallTransport response budgets, certificate-feed stalled-body cancellation, source object/pixel/image limits, extraction scratch/worker budgets and comprehensive low-storage/Content-Encoding/redirect integration still need work. Cleanup-deletion faults and physical phone storage/background behavior need dedicated validation. This report does not call all those paths bounded or tested. R8 job coordination remains separate; only downloader cancellation registration/finalization is addressed here. R3 app-model integration should be retested after reviewed branches integrate.
