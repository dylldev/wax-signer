# R6 App ID prefixes independent of Team IDs

Baseline `8ad4b2e`. Original ProfileReader ignored ApplicationIdentifierPrefix; ProfileInfo.bundleIdentifierPattern/ProfileFitness removed only Team ID; BundleSigner formed application-identifier and EntitlementsPolicy rewrote keychain groups with Team ID. A historical prefix differing from TeamIdentifier therefore failed matching or generated incorrect identity entitlements.

The actual application-identifier entitlement now defines a validated 10-character App ID prefix. A present ApplicationIdentifierPrefix list must contain it and be structurally valid; a missing legacy field infers it from that entitlement. Team ID remains separate for certificate matching, team entitlement and CodeDirectory. Pattern selection/rename, keychain grant checking and application identifiers use the prefix, including nested bundles and deliberate fixed-ID keep mode. Requested groups are still checked against actual grants; nothing is broadened. App ID prefix is computed from the already persisted applicationIdentifier, so old Codable profile indexes remain readable without rewriting them. Credentials detail exposes the prefix; signing warns if a previous application identifier's prefix changes and may affect keychain continuity. A complete read-only pre-signing preview remains dependent R15 work, not claimed here.

Eight new deterministic AppIDPrefixTests cover distinct prefixes, absent/invalid/inconsistent/multiple declared lists, legacy metadata decoding, exact/prefix/full wildcards, strict keychain grants, actual nested signing, keep/rename, local signature verification and macOS codesign/TeamIdentifier extraction. Test profiles are explicitly unsigned synthetic CMS containers, never represented as Apple-trusted. Existing fixture private keys are unchanged; no new key material.

Available checks: Swift frontend parsing passed. Seven isolated assertions compiled/executed against the actual Foundation-only ProfileInfo/ProfileFitness sources on Linux. EntitlementsPolicy's existing Objective-C AnyObject equality cannot compile on Linux; no portable substitute is claimed to verify Apple signing. New Apple-dependent tests and full package/iOS checks require final macOS CI. No device update/keychain continuity, installation or launch is claimed. Real distinct-prefix profiles require owner-authorized device validation. Malformed prefix declarations now reject clearly; valid same-prefix fixtures should retain semantics and remain covered by existing tests. See PR/master checkpoint for exact final CI, not an inferred success.
