# R5 isolated OTA upload transactions

Baseline `8ad4b2e`. Original `Server/wax-ota/wax_ota.py:154–192` used a shared `.<filename>.part`; independent open writers could modify an acknowledged IPA. Upload, hash lookup, GC and DELETE had no common session ownership.

Unique mkstemp files, nonblocking per-session mutation admission (409), 16-reader capacity (503), protected GC/DELETE, accurate staged quota accounting, bounded read1 deadlines and post-cleanup responses replace that lifecycle. Publication is a single IPA rename. Inode-bound optional hash cache records are candidate prefilters, with actual streaming SHA-256 verification on hits; cache failure after publication is an actual 201 upload with warning/cache miss, not a false failure. Failures before publication preserve previous IPA/hash. Legacy plaintext cache becomes a miss, not an incorrect hit. Existing auth, allowed names, loopback binding and Caddy hidden-file rules remain. Header idle timeout and ambiguous body framing rejection supplement existing size/deadline limits.

Local `python3 -m unittest discover -s Server/wax-ota -p 'test_*.py'`: 55 tests / 0 failures / 0 skips. New cases use events to pause actual server transactions, not sleep-based race assumptions. They cover overlapping IPA/manifest/DELETE, other sessions, GC, aborted bodies, hash mismatch, publication and cache failure, cleanup retention and symlink containment. The initial new suite exposed responses occurring before cleanup/session release; corrected and regression retained.
