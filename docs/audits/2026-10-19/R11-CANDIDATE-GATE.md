# R11 milestone — Tagged-source release candidate gate

Stacked on R4 `4534231`, target `codex/r4-distribution-correctness`; source-built probe acceptance additionally requires reviewed R12 integration before an actual new release can be prepared. No dependency code duplicated and no tags/releases/deployments created in the real repository.

Baseline `scripts/build-release-ipa.sh:6–25` builds the working tree and moves an IPA/hash into output without source-tag/probe/provenance mapping. R4 validates artifact/feed bytes, but not their selected source/build context. New `Source/prepare_release.py` wraps the existing build in a fresh export of an explicit annotated tag at HEAD. It records the actual commit/tag object/export hash and refuses a changed tag after building. Ignored/untracked local secrets cannot become source inputs; child environment carries only essential Mac tool settings and explicitly public configuration. The existing build script writes only into owned temporary output.

The staged IPA must agree with tag version, requested build, official bundle ID and requested embedded configuration. Source-built probe evidence must agree with actual physical-iOS platform/nested ZIP/executable bytes and exported public sources. R4 generates/validates the stage from those actual bytes; a sidecar manifest binds source/toolchain/configuration/staged artifact. No output candidate appears until gates pass, and existing candidates are refused. History retention is an explicit CLI choice; unsupported cross-bundle migration is not guessed. No install capability is inferred merely from having a configured feed.

Local `python3 -m unittest discover -s Source -p 'test_*.py'`: **25 tests /0 failures /0 skips** (15 R4 +10 candidate regressions). Fixtures use throwaway annotated Git repos and synthetic structurally shaped IPA/probe ZIPs; they do not claim an actual compiled/signed app. Coverage: staged hash/source binding, ignored/untracked exclusion, tag/build/HEAD checks, missing probe, moved tag, extra artifact/source mismatch, configured/no-feed input, failure cleanup and existing-output preservation. Full macOS CI remains required on final head. The live release-build path was not executed: no independently reviewed release tag/new release artifact is available and this Linux host lacks Xcode.

Original R11 is only partially complete: owner-protected tag/review policy, pinned build tools/actions, immutable CI evidence binding, protected promotion, deployed-byte comparison and rollback rehearsal remain. New `Source/RELEASE-CANDIDATES.md` supplies the actual manual preparation/review protocol. Manifest explicitly says Apple conformance/physical install/launch NOT_RECORDED and bit reproducibility NOT_ESTABLISHED. A manifest is not a cryptographic attestation. No claim that a prepared candidate is release approved.
