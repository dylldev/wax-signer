# Build on the records Wax already keeps

These 48 proposals address distinct user problems. Some are repairs, some extend a shipped mechanism, and others buy a feasibility answer. The scores represent editorial engineering judgment. They do not measure demand, speed or safety. A low product score cannot displace a hard release gate. Dates in a milestone name indicate sequence only. Effort excludes device, certificate-holder and review availability.

## Score each proposal on seven inputs

Each input ranges from 0 to 10. V is user value (25%), R reliability/security (20%), D differentiation (15%), F feasibility (15%), E implementation efficiency (value for the engineering effort) (10%), S maintenance sustainability (10%) and Q strength of available evidence (5%). Ten is favorable on every input. Weighted points out of 100 equal the sum of each input times its percentage weight divided by ten. A feasibility score on a spike estimates the ability to answer its question, not product support. Small score differences do not establish a meaningful preference.

## What each proposal would change

**I01 · Profile truth labels.** A user cannot tell an intact profile from an Apple-trusted profile. Separate integrity, chain trust and unknown revocation in Credentials. Correct existing copy. Work touches CredentialKit + CredentialsView / Security CMS. No online certificate lookup. Keep trust classification honest. One trust mapping per view update; no extra network call. Feasibility 9/10. Estimate 0.5–1 engineering days, low upkeep. Target 0.17.

**I02 · Identity readiness parity.** A shelf identity can look usable until preparation. Compare the runtime leaf fingerprint with saved selection before either operation. Local-only guard, public check incomplete. Work touches CredentialKit + CredentialsModel / Keychain. Fail closed on mismatch. Avoid expensive reload on every redraw. Cache only nonsecret readiness metadata within its validity window. Feasibility 8/10. Estimate 2–4 engineering days, medium upkeep. Target 0.17.

**I03 · Normal candidate attestation.** Release packaging expects a Dev probe inside normal Wax. Record separate channel contracts and verify actual bytes. Repair existing provenance. Work touches Source / Xcode build channels. Keep secret scanning and probe digest validation. No network needed. Hashing artifacts adds release-time I/O, outside the normal app. Feasibility 9/10. Estimate 1–3 engineering days, low upkeep. Target 0.17.

**I04 · Readable confirmation.** People using large text cannot reach every signing control. Use wrapping labels, stacked actions and stable focus order. Draft partial. Work touches App / Dynamic Type + VoiceOver. Preserve confirm/cancel semantics and avoid implicit double actions. Measure AX layout without increasing redraws on progress updates. Feasibility 9/10. Estimate 1–3 engineering days, low upkeep. Target 0.17.

**I05 · Honest save outcome.** A failed shelf save can look final. Offer retry and export from the retained signed result. Draft PR #33 partial. Work touches SigningModel + views / Files. Never discard last good output to repeat a save. Keep one signed temporary result bounded by the existing job lifetime. Feasibility 9/10. Estimate 1–2 engineering days, low upkeep. Target 0.17.

**I06 · Duplicate import explanation.** Someone importing the same app twice cannot distinguish duplicates from builds. Explain equal bytes versus identical metadata. Digest matching exists, explanation extension. Work touches IPALibrary + LibraryView / Files. Reuse stored SHA and revalidate bytes on adoption. Hash work stays bounded by the existing library verification policy. Feasibility 9/10. Estimate 1–2 engineering days, low upkeep. Target 0.18.

**I07 · Private host destination card.** Users cannot see who gets a signed app. Display HTTPS origin, retention and credential scope before upload. Existing server, new disclosure. Work touches InstallKit + install UI / HTTPS operator. Hide tokens, strip query strings, never auto-upload. URL formatting should not trigger DNS or session startup. Feasibility 9/10. Estimate 1–2 engineering days, low upkeep. Target 0.18.

**I08 · Export after delivery failure.** A failed upload makes a person think signing failed. Offer the exact retained signed item and retry delivery only. Existing saved snapshot, UX extension. Work touches IPALibrary + OTAInstallModel / Files. Hash snapshot before reuse. Use one upload owner. Budget temporary space for the private snapshot before retry. Feasibility 9/10. Estimate 1–2 engineering days, low upkeep. Target 0.18.

**I09 · Update continuity preview.** An ID change can break access to saved data. Compare proposed identity, prefix and groups against last shelf record. Extend IdentityContinuity, no installed-app inventory. Work touches SigningRecord + SigningPlan / iOS upgrade rules. Keep prior IDs local. Never promise data retention from metadata alone. Compare a bounded record, never scan device-installed apps. Feasibility 8/10. Estimate 2–4 engineering days, medium upkeep. Target 0.18.

**I10 · Provider import recovery.** A cloud placeholder may disappear mid-import. Explain how to reacquire it while keeping the prior shelf intact. Import checks exist, provider journey incomplete. Work touches IPAKit + LibraryModel / document provider. Acquire scoped handle only during copy. Enforce disk budget. Read in bounded chunks and stop promptly on provider cancellation. Feasibility 8/10. Estimate 2–3 engineering days, medium upkeep. Target 0.18.

**I11 · Low-space explanation.** Users need to know which files need free space. Surface required and available scratch before preparation. Expose existing budgets. Work touches IPAKit + prepared UI / volume capacity. Use conservative estimates and offer export/cleanup without deleting originals. Avoid a recursive disk scan on the main thread. Feasibility 9/10. Estimate 1–2 engineering days, low upkeep. Target 0.18.

**I12 · Stage-specific cancel.** Someone cancelling during packing must know whether anything was published. Show cancellation phase and retained output. Extend existing cancellation seal. Work touches PreparedIPA + BackgroundJob / finite OS time. Check ownership and keep cancellation off publication boundary. Measure cancel-to-idle latency on large files. Feasibility 8/10. Estimate 2–3 engineering days, medium upkeep. Target 0.18.

## Reject or postpone five proposals

| ID | Proposal | Decision |
|---|---|---|
| X01 | Guaranteed silent refresh | iOS schedules background work and the user can force quit. Use explicit renewal and best-effort reminders. |
| X02 | Trust-bypass installation | HTTP, disabled hostname checks or a blanket root weaken the supported route. Preserve export and valid HTTPS. |
| X03 | Decrypt commercial encrypted IPAs | Outside the authorized, unencrypted input contract and unrelated to signing conformance. |
| X04 | Universal entitlement restoration | A user interface cannot mint Apple-granted capabilities. Explain dropped or rewritten entitlements. |
| X05 | Hosted Apple Account provisioning in 1.0 | Adds authentication, credential custody, upstream outages and support obligations. Reconsider only as a separately owned product decision. |
