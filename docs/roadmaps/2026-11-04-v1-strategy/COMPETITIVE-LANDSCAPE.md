# Compete on evidence people can inspect

Feather is the closest product comparator for people bringing their own certificates. AltStore Classic and SideStore address account provisioning and refresh. LiveContainer runs apps inside a host, changing the meaning of installation, isolation and extension support. Wax's credible opening is a clear preflight, a preserved verified output and honest recovery after a failed delivery. Maintainer claims describe product behavior. Comparative speed, peak memory, failure rates and security ratings remain unknown.

## Libraries provide test cases and design references

**zhlynn/zsign**, MIT, v1.1.3 on 2026-10-20: native signer and inspection reference. Supports per-extension profiles, dylib injection/removal, metadata, certificate/OCSP inspection and persistent signature cache. V1.1.2 fixes profile placement before resource sealing. V1.1.3 refuses unreadable files instead of sealing empty data. These are concrete correctness lessons for Wax tests. Its `--adhoc` hash-only signature is not Apple's Ad Hoc provisioned distribution. No timing comparison was run. [Pinned README](https://github.com/zhlynn/zsign/blob/9299685bab7ef99827e06e5dfda93af747386590/README.md). [v1.1.2](https://github.com/zhlynn/zsign/releases/tag/v1.1.2). [v1.1.3](https://github.com/zhlynn/zsign/releases/tag/v1.1.3).

**SideStore/SideSign**, README declares GPL-3.0 despite GitHub metadata returning no detected license. Active 2026-10-13, release 0.1.7 on 2026-09-13. Swift signing/provisioning library with CodeSignKit, GSACryptoKit and streaming libdeflate archive support. Promising comparison for entitlement rewriting and archive design, with Apple authentication protocol maintenance risk. Verify actual LICENSE and transitive obligations before reuse. [Pinned README](https://github.com/SideStore/SideSign/blob/752d1ef602aa792a432ffa1e71646dc1ecf7363c/README.md).

**jkcoxson/idevice**, MIT, active 2026-10-27, release 0.1.68 on 2026-09-15: Rust device-service library with installation_proxy, profiles, diagnostics and logging. Maintainer explicitly calls API research-stage and warns point releases break API until 0.2.0. It is an installation/diagnostics building block, not an IPA signer or stability guarantee. [Pinned README](https://github.com/jkcoxson/idevice/blob/89702099f4d7552f704f93b4526756abda319ceb/README.md).

**Lakr233/Asspp**, MIT, release 4.2.2 on 2026-10-20: adjacent iOS 17+/macOS 15+ App Store/account/download/library UX comparator, not a general decrypted IPA signer. README flags undocumented protocol fragility and labels proposed outage causes speculation. Do not repeat those causes as facts. [Pinned README](https://github.com/Lakr233/Asspp/blob/6682eb8f831a7b5c62dc14ea97088769c6adba48/README.md).

**ProcursusTeam/ldid**, AGPL-3.0, code pushed 2026-07-24 but latest tagged release from 2023: relevant entitlement/signature inspection/signing component, not whole provisioning/installation product. `opa334/ldid` was last pushed 2023-11-28. Distinguish fork identities. [Procursus repository](https://github.com/ProcursusTeam/ldid/tree/af86971ae72ec3ed3d0a699107c4e882324c941b). **blacktop/ipsw**, MIT, v3.1.741 released October 31, host-side Apple artifact/Mach-O inspection candidate. Useful to triangulate fixtures/reports, not a runtime dependency recommendation. Its broad feature set, exact relevant commands and equivalence to Apple's verifier need a separate evaluation. [Pinned repository](https://github.com/blacktop/ipsw/tree/e6612ee1963602a62192ec375f9fa6be17198fdf).

**jveko/zsign-rs**, active 2026-10-14, no release returned. README/manifests claim MIT while GitHub reports NOASSERTION. Keep outside the mature baseline. **zwsn/zsign-ios**, Apache-2.0 wrapper metadata, last push 2024-01-21, no releases. **isignpy/isign**, last push 2021-05-15, no releases, NOASSERTION license detection. A benchmark needs the same device, input, credential type, output settings, warm-up and timing boundaries. Comparing a Wax engine interval to another app's full UI journey would misstate its speed.

## Apple feasibility sets the support boundary

Five classes apply to individual claims. **Officially supported** means Apple documents a primitive or distribution context. **Demonstrated** means maintained source or a scoped observation shows behavior. **Configuration dependent** requires a particular device, profile, host or entitlement. **Plausible, unverified** needs an independent experiment. **Platform-blocked** covers guarantees an app cannot make under iOS policy.

| Capability | Classification | Evidence and limits for a v1 promise |
|---|---|---|
| Import an Apple Development or Apple Distribution identity | Officially supported primitive. Configuration dependent use | Apple distinguishes development, distribution and macOS Developer ID certificates. Distribution to registered iOS devices requires the appropriate certificate/profile. A generic “valid certificate” check cannot prove installability. [Certificates overview](https://developer.apple.com/help/account/certificates/certificates-overview/). [registered-device distribution](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices) |
| Use a provisioning profile to authorize an app | Officially supported | The profile binds who signs, app identity, allowed devices, time and entitlements. A certificate alone cannot grant capabilities. DER profile data, not only the plist view, is the modern source of truth. Parsers need ongoing compatibility work. [TN3125](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles) |
| Rewrite App ID prefix, bundle ID or Keychain groups during re-signing | Configuration dependent | Signed entitlements must match the profile. App ID prefix is not safely interchangeable with Team ID. Changing identity can break updates and Keychain access. [TN2415](https://developer.apple.com/library/archive/technotes/tn2415/_index.html). [QA1726](https://developer.apple.com/library/archive/qa/qa1726/_index.html) |

Use explicit “update existing” versus “install separate copy” UX and warn before identity changes. [TN2319](https://developer.apple.com/library/archive/technotes/tn2319/_index.html) |

This is a source/design finding, not a fresh key-extraction or backup test. [Wax SECURITY](https://github.com/dylldev/wax-signer/blob/62ff68b72f27e9e33987a87a48f27765369e126f/SECURITY.md). [LiveContainer limitations](https://github.com/LiveContainer/LiveContainer/blob/9108ae624ea001f7d7696d48407f890b48fa2653/README.md). [TN2319](https://developer.apple.com/library/archive/technotes/tn2319/_index.html) |

**Default.** Preserve the signed file and offer export. For direct delivery, qualify the operator's HTTPS endpoint behind its intended proxy. Require a valid server-specific certificate, scoped upload credential, short-lived random download URL, deletion or expiry, and a tested fallback. The operator can see the uploaded IPA. The phone's signing identity stays on the device. Validate authorization and quotas at the server as well as the client.

**Experimental.** An honest loopback precheck checks Wax's lookup. The system installer resolves later. An attacker with control over the installer’s later name resolution and the published TLS key can redirect the manifest or IPA connection or disrupt delivery. IOS still validates signing/profile authorization. The public key holder can request certificate revocation without controlling DNS, impairing availability for everyone using that identity.
