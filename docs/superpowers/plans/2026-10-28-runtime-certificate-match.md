# Runtime certificate validation plan

Goal: reject a runtime certificate that differs from the selected imported certificate and prevent a misleading Ready badge. Dylan approved this bounded scope in chat on 2026-10-28. Keep personal credentials intact and normal Wax free of diagnostic controls.

Use the existing SHA-1 fingerprint index to compare exact certificate DER identity. This checks association with saved metadata; it does not establish certificate trust. Do not weaken existing signer/profile checks. The specific physical Ad Hoc root cause remains unconfirmed.

1. CredentialStoreTests: swap a stored fixture identity for a different real fixture identity. Assert identity retrieval throws and stored index/keychain remain unchanged. Run `mobilebuildmcp swift-package test --package-path . --filter CredentialStoreTests`. Red observed: retrieval did not throw. Add certificate copy and fingerprint comparison in CredentialStore.identity(for:); throw new CredentialError.identityMismatch. Preserve the missing-ID path and avoid holding the metadata lock during Keychain access.
2. AppModelTests: prove metadata-only readiness cannot return Ready; exercise background validated lookup for matching, mismatched and missing identities and stale results after cancellation/deletion. Add a per-certificate result map to CredentialsModel, reset on refresh, use a generation token and certificate snapshot to discard stale results. No lookup in SwiftUI rendering. Readiness returns Check until a validated result exists. Retain expiry/profile evaluation and existing development-only test records.
3. Connect one root task keyed by certificate metadata plus an app-foreground refresh. Route identity badges through the result map. Show the typed recovery message on the Credentials card and preserve the same error from signing. No automatic deletion or reimport.
4. Run full package tests, app-model simulator tests and hosted Keychain tests. Run regression red/green/reverted-red/restored-green. Both build channels must compile. Refresh Graphify once and inspect diff. No phone installation, publishing or push.

Review: three distinct free reviewers completed in artifacts/wax-certificate-match-20261028/panel-retry. Lightning supported exact runtime validation; Super VL highlighted stale readiness, main-thread blocking and fail-closed behavior; North supported the plan. Their claims about a physical root cause are unverified. SecIdentity validation occurs again at each signing retrieval; readiness never authorizes signing. Metadata comparison rejects different certificates without deleting any Keychain item.
